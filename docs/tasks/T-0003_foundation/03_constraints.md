# Umsetzungsgrenzen

- Vollständiger Plan ausdrücklich beauftragt; Codeänderungen und normale Entwicklungsprüfungen autorisiert.
- Momentum bleibt unverändert. Jede Helferinstallation/-version vorher konkret zur ausdrücklichen Freigabe vorlegen.
- Größeren UI-Umbau erst nach sichtbarer Entwurfsprüfung durchführen.
- Kein öffentlicher Release vor Kernabnahme. CI zunächst ausschließlich Testartefakte; keine Upstream-Uploads.
- Keine Simulatoren. Schwere Builds bevorzugt CI; kleine portable Kernchecks lokal mit zwei Build-Prozessen.
- MCP-Vollfreigabe lokal je Computer. Ressourcenwechsel, Helferfreigabe und Backup-Sperre bleiben wirksam.
- Enumerierbare UI-Werte als Auswahl. Kein Squash-Merging.
- Produktgrenzen nicht stillschweigend ändern; technische Blockaden konkret dokumentieren.
